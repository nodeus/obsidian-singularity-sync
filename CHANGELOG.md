# Changelog

## 2.9.0 (2026-10-14)

### Added
- **Календарь в создании задачи**: поля дат модалки — нативные пикеры (`type="date"`, для напоминания отдельно `type="time"`), кнопки «Сегодня» и «✕» в каждой строке. Ручной ввод и оба формата напоминания (с временем / только дата) сохранены.

### Fixed
- **Выполненные задачи больше не спамят файлы проектов**: reverse переводит совпавшие строки в `[x]`, но не создаёт новых строк для выполненных/отменённых (`merge-only`, считаются в `skipped`).
- **Массовые 500 на PATCH задач**: `timeLength: 0` больше не отправляется (ни в create, ни в update); `⏱ 0m` парсится как отсутствие длительности, legacy-токены вычищаются нормализацией.
- **400 на отправку таймера**: `POST /time-stat` шлёт обязательный `source: 1` (stopwatch).
- **Утечка ID тегов**: промах кэша имён тегов больше не пишет сырой ID как `#uuid`; UUID-образные теги в forward пропускаются.
- **Batch**: настоящие UUID v4 в операциях (сервер 400ил весь конверт иначе); задачи без названия не синкаются вообще (тоже травили batch).
- **Протухший ключ не прилипает**: 401 чистит кэш ключа и включает cooldown ядра панели на 5 минут; в уведомлении — источник ключа для диагностики.

## 2.8.0 (2026-10-13)

### Added
- **Подзадачи**: строки `- [ ]` с отступом синкаются как подзадачи Singularity (связь `parent`, таб/2 пробела — уровень). Дети ставятся сразу за родителем; в сайдбаре — префикс `↳`.
- **Заметки задач**: заметка задачи из Singularity попадает в якорный блок `%% task:T-ID %%` в секции заметок её проекта (только чтение; правки в Obsidian сохраняются, но не отправляются).
- **CI**: workflow test+build на push/PR в develop/main (`tsc` non-blocking до чистки бейзлайна).

## 2.7.0 (2026-10-13)

### Added
- **Повторяющиеся задачи (только чтение)**: задачи Singularity с повторениями синкаются в Obsidian с правилом Tasks `🔁` (`every day`, `every week on Saturday`, `every month on the 30th`, `… when done`). Правило отображается в строке, сайдбаре (бейдж) и диалоге конфликтов. API не умеет записывать повторения — завершайте такие задачи в Singularity.

### Fixed
- **Порядок строки совместим с Tasks и Reminder**: длительность `⏱` сразу после описания (иначе Tasks не видел даты), срок `📅` сразу за напоминанием `⏰` (иначе Reminder терял пару).

## 2.6.0 (2026-10-13)

### Added
- **Локальный журнал трекинга**: вкладка `⏱ Журнал` в сайдбаре — остановленные сессии (дата, задача, старт → финиш, длительность) с копированием строки в буфер одним кликом. Для ручного переноса времени в Singularity.
- **Время таймера везде**: время старта в статус-баре, живой счётчик в строке задачи (тик раз в 30 сек), старт → финиш в уведомлении об остановке.
- **Только локальный трекинг**: настройка для тарифов без time-stat API — стоп без запросов в сеть и шума 403; API-бейджи времени скрываются.

### Fixed
- **403 при остановке таймера**: понятное уведомление про scope токена вместо generic-ошибки; данные всегда сохраняются в локальный журнал.
- **Старт таймера без API-ключа**: запуск — полностью локальный, ключ нужен только для отправки.

## 2.5.1 (2026-10-12)

### Fixed
- **Чек-листы на дельта-синке**: предметы задач, не менявшихся с прошлого синка, ошибочно пропускались как «входящие». Теперь родительская задача догружается точечно — предметы доходят и на дельте.
- **Тихие пропуски чек-листов**: отсутствующий файл проекта и итоги прогона (`прочитано/записано/пропущено`) теперь видны в консоли вместо молчания.
- **Спам 403 в сайдбаре**: декоративные запросы (секции, канбан, время) больше не шумят в консоль; при нехватке scope токена — одно понятное уведомление за сессию и пропуск повторов.
- **Боксы без якоря**: если в секции нет ни одного якоря, а боксы без `%% chk:ID %%` есть — одно уведомление вместо тишины.

## 2.5.0 (2026-10-12)

### Added
- **Создание задачи из редактора**: правый клик в тексте → `➕ Задача Singularity` → модалка со всеми полями (название, статус, приоритет, проект, даты `➕ ⏰ 🛫 ⏳ 📅`, длительность `⏱`, теги, уведомление). Строка собирается в каноническом формате, проект по умолчанию — из текущего файла.
- **Умная вставка по проекту**: если выбранный проект совпадает с файлом курсора — вставка в курсор; если другой — задача дописывается в конец секции задач целевого проекта (файл/секция создаются при отсутствии). После вставки запускается синхронизация.

## 2.4.0 (2026-10-12)

### Added
- **Инкрементальная синхронизация**: полная синхронизация — при первом запуске и раз в 24 часа, между ними reverse тянет только изменённые задачи (`modifiedSince`). Режим виден в итоговом уведомлении («полная»/«дельта»).
- **Чек-листы**: пункты чек-листов Singularity синхронизируются как строки `- [ ] название %% chk:ID %%` в секции `#### 📝 Notes` файла проекта. Якорь может стоять в любом месте секции; переключение бокса, переименование и удаление строки доходят до Singularity.
- **Длительность задач**: токен `⏱ 30m / 2h / 1d / 1h30m` двусторонне связан с `timeLength` в Singularity; смена длительности видна в диалоге конфликтов.
- **Секции проектов**: названия секций (task groups) показываются в сайдбаре (`📂`) и в диалоге конфликтов.
- **Таймер трекинга времени**: кнопки ▶/⏹ в строках сайдбара, состояние переживает перезапуск Obsidian, остановка пишет запись времени в Singularity. Команда палитры «Остановить трекинг», суммарное время за 30 дней — бейджем `⏳` у задачи.
- **Смена канбан-колонки из сайдбара**: выпадающий список колонок проекта в строке задачи.
- **Проектные бейджи**: иконка 📓 у блокнотов, цветные точки проектов, честный счётчик «Показано N из M».
- **«Применить ко всем» в диалоге конфликтов**: выбор запоминается до конца синхронизации; в заголовке — номер конфликта; `Esc`/крестик больше не вешают синхронизацию (считается пропуском).
- **Настройка удаления проектов**: удаление файла проекта удаляет проект в Singularity только при включённой опции (по умолчанию выключено — проект живёт, файл не пересоздаётся).
- **Диагностика**: каждый запуск имеет `runId` (виден в консоли и в `data.lastSync` вместе с режимом, длительностью и счётчиками); уведомления об ошибках API троттлятся.

### Changed
- **Создание задач — одним batch-запросом** вместо N одиночных (с поштучным fallback при ошибках); удаление задач — тоже батчем.
- **Статусные переходы** (выполнить/отменить/архивировать/переместить) идут через семантические endpoints API вместо сырого PATCH.
- **Хэши задач** переведены с 32-битного djb2 на 53-битный cyrb53 (меньше риск склейки чужих задач). Старые связи подхватываются автоматически при первой синхронизации.
- **Повторы запросов**: чтение — до 4 попыток (429/5xx/сеть) с экспоненциальной паузой; записи — максимум 1 повтор и только при сетевой ошибке; 400/401/403/404 не ретраятся.
- **Параллельные запуски** синхронизации отклоняются с уведомлением.
- **Проверки перед синком**: некорректные пути/маркеры/URL и отсутствующий API-ключ прерывают запуск до любых изменений.
- **Сохранение настроек** — с дебаунсом 500 мс вместо записи на каждый символ.

### Fixed
- **Дубли при офлайне/401**: ошибка загрузки проектов/задач больше не трактуется как «на сервере пусто» — синхронизация прерывается до любых записей (`SyncAbortError`).
- **Дубли при переносе между файлами**: relink по content-хэшу работает через все файлы, старые записи чистятся; удаление+пересоздание ушло.
- **Потеря `⏰/🛫/⏳` из Singularity**: reverse merge теперь подтягивает SG-даты в Obsidian.
- **Потеря текста заметок**: первая запись секции `#### 📝 Notes` теперь сохраняется на диск (ранее вычислялась и отбрасывалась).
- **Парсинг**: `[X]` считается выполненной; U+FE0F с мобильных клавиатур; дубли `📅…📅…`; `#notify/5H` = 300 минут (был 5); пустой приоритет больше не становится High; время в `➕/✅/❌` не течёт в описание; лишний `}` в нормализаторе не ел скобки в заголовках.
- **Строгий парсинг дат**: голый `"2026"` и `true` больше не превращаются в даты 1970/2026; невалидные даты бросают до HTTP 400.
- **DST-сдвиг**: offset вычисляется на саму дату, а не «на сейчас» (до ±1ч ошибки на летнем/зимнем времени).
- **Заметки — не задачи**: сущности `isNote` исключены из матчинга и сайдбара.
- **Имена проектов** санитизируются в путях (`A/B`, `../x` больше не ломают файлы).
- **Чекбокс сайдбара** больше не врёт при сетевой ошибке (disabled + откат).
- **Рендер Delta-заметок**: code-блоки — один fence на серию, таблицы — построчно.

## 2.3.0 (2026-08-03)

### Added
- **Ручное разрешение конфликтов**: при стратегии «Вручную» (Manual) синхронизация больше не решает конфликты автоматически — открывается диалог с обеими версиями задачи. Доступные действия: оставить версию Obsidian, оставить версию Singularity, создать новую задачу в Singularity (при неоднозначном сопоставлении) или пропустить до следующей синхронизации.
- **Понятный интерфейс конфликт-диалога**: каждая версия задачи показывается полями (статус, приоритет, проект, теги, даты, уведомления) в едином порядке, расхождения подсвечиваются бейджами «⚠️», сверху — сводка того, что различается. Даты отображаются в локальном часовом поясе.

### Fixed
- **UTF-8 BOM в релизных файлах**: BOM, добавленный редакторами в `manifest.json`/README при сборке релиза, ломал публикацию через `release:publish` (ошибка `JSON.parse`). Файлы релиза теперь собираются без BOM, `release:publish` дополнительно страхуется от него.

## 2.2.3 (2026-08-02)

### Fixed
- **Ошибки 404 в консоли при синхронизации**: удалённые в Singularity задачи (и проекты) генерировали ошибки в консоли разработчика и уведомления «⚠️ API 404». Теперь ожидаемые 404 тихо возвращают `null` — логируются только реальные ошибки API. Логика синхронизации не изменилась: такие задачи корректно пропускаются.

## 2.2.2 (2026-08-02)

### Fixed
- **HTTP 400 при синхронизации**: Singularity API v2 отвергает даты без таймзоны (`"2026-08-02T15:00:00"`) и date-only (`"2026-08-02"`) для всех datetime-полей (`start`, `deadline`, `journalDate`, `deleteDate`). Все даты теперь отправляются с локальным timezone offset (например `"2026-08-02T15:00:00+05:00"`) — создание и обновление задач снова работают.
- **Потеря дат при обновлении**: `updateTask()` молча отбрасывал `deadline`/`start`/`useTime` — изменения сроков и напоминаний не доходили до Singularity. Исправлено.
- **`createdDate` убран из создания задач**: поля нет в API v2 — при отправке всегда возвращался 400.
- **Секция задач стиралась при синхронизации**: `writeTasksToFile()` заменял секцию `#### 📝 Tasks` пустыми строками, удаляя задачи из файлов проектов. Теперь секция мержится: поля из Singularity обновляются, Obsidian-даты (`⏰🛫⏳➕✅❌`) сохраняются, несовпавшие строки остаются, новые задачи добавляются в конец.
- **Накопление пустых строк**: секция «распухала» на каждой синхронизации (до 5+ пустых строк). Теперь пустые строки схлопываются в одну-единственный разделитель.
- **Исчезающий `📅`**: срок выполнения сохраняется из существующей строки, если Singularity вернул пустой deadline.

### Changed
- Даты отправляются с локальным timezone offset (ранее — без него), в соответствии с требованиями API. Round-trip сохраняет локальное время (`⏰ 2026-08-02 15:00` ↔ `start: 2026-08-02T15:00:00+05:00`).

## 2.2.1 (2026-06-17)

### Fixed
- **Task disappearance on sync**: reverse sync timestamp check (`sgMod <= lastKnown`) пропускал задачи с `externalId`, которые только что создал forward sync. Поскольку `writeTasksToFile` заменяет секцию целиком, пропущенные задачи удалялись из файла. Теперь задачи с `externalId` никогда не пропускаются — они всегда включаются в `tasksToWrite`.
- **Unnecessary vault.modify calls**: `writeTasksToFile()` вызывал `vault.modify()` даже при идентичном содержимом, что меняло `file.stat.mtime` и провоцировало лишние API-обновления. Теперь содержимое сравнивается перед записью.

## 2.2.0 (2026-06-17)

### Added
- **⏰ Reminder support**: поле `reminderDate` (эмодзи `⏰`) — дата и время напоминания. Вычисляется из `notifies` + `deadline` (reverse sync) или из `⏰` в строке задачи (forward sync).
- **`notifies` → `⏰` forward mapping**: при forward sync `⏰` + `📅` конвертируются в массив `notifies` (минуты до дедлайна). Пользователь может редактировать `⏰` — изменения попадут в Singularity.
- **`start` → `⏰` mapping**: если `start` в Singularity содержит время и `notifies` задан — маппится в `⏰` (а не в `⏳`). Время **только** в `⏰` — совместимо с Obsidian Tasks Plugin.
- **Standard task format**: `formatTaskLine()` генерирует задачи в строгом порядке: `#todo desc #tags ➕ ⏰ 🛫 ⏳ 📅 🔼 #notify`.
- **StableHash (dedup)**: `computeStableHash()` — хеш описания без метаданных (теги, даты, эмодзи). При изменении описания задача перелинковывается через `TaskStore` вместо создания дубликата.
- **Project transfer**: перемещение задачи между проектными файлами + изменение описания корректно обновляет `projectId` в Singularity через stableHash fallback.
- **Normalize task order**: `normalizeTaskLines()` перезаписывает строки задач после forward sync в стандартном порядке.
- **Quiet API mode**: `_req()` принимает `quiet` — подавляет `console.error` и `Notice` для ожидаемых 404 (используется в `setHabitProgress()`).

### Fixed
- **Tasks wiped on sync**: `writeTasksToFile()` с пустым массивом задач стирал секцию `#### 📝 Tasks`. Теперь `if (processed.length === 0) continue;` предотвращает запись пустых массивов.
- **Completed tasks not syncing**: forward sync архивировал задачи в SG, но reverse sync пропускал их (timestamp match). Добавлен трекинг `_archivedIds` — reverse sync обрабатывает заархивированные задачи.
- **⏰ without notifies**: `start` с временем генерировал `⏰` даже без `notifies` в API. Теперь `reminderDate` устанавливается только если `notifies.length > 0`.
- **Time loss on 🛫/📅**: `formatTaskLine()` использовал `.split(" ")[0]` для `startDate`/`dueDate`, теряя время. Исправлено — время отображается только в `⏰`.
- **Habit progress 404 Notice**: `_req()` показывал `Notice` для ожидаемого 404 при PATCH привычек. Добавлен `quiet` режим.
- **`generateTaskId` regex order**: emoji-даты теперь-stripаются перед эмодзи приоритета (порядок `ALL_EMOJI_DATE_RE` → `ALL_EMOJI_RE`).
- **⏰ only from start**: `⏰` теперь ТОЛЬКО из поля `start` (ранее fallback из `deadline - notifies`).
- **#notify from ⏰ only**: `#notify` генерируется только из `start`, не из `deadline - start`.
- **Local time to API**: `formatDateForApi()` отправляет локальное время без `Z` (Singularity ожидает local time, не UTC).
- **notifies[0] for ⏰**: если `⏰` задан без `#notify` → отправляется `notifies: [0]` (напомнить ровно в время `⏰`).

### Changed
- **`notify` (singular) и `alarmNotify`**: read-only в API, больше не отправляются при создании задач.
- **Reverse sync timestamp skip**: reverse sync пропускает SG-задачи, не изменённые с последней синхронизации (`modificatedDate <= lastModifiedSingularity`).

## 2.0.1 (2026-05-19)

### Fixed
- **Cancelled task support**: строки `[-]` теперь корректно парсятся и записываются. Добавлен статус `TaskStatus.Cancelled` (checked=2).
- **Priority display**: `🔺` используется для всех задач высокой важности (вместо `⏫`). Оба символа `⏫` и `🔺` парсятся как `Priority.High`.
- **Null-propagation в API-клиенте**: значения `null` корректно отправляются в API для очистки полей (даты, теги). Защита от случайной зачистки SG-тегов пустым массивом.
- **Round-trip стабильность**: Phase 2a guard проверяет статус задачи в SG перед skip-ом — предотвращает ложное срабатывание на основе хеша.
- **Soft-delete защита**: `syncDeletedObsidianTasks()` проверяет refCount SG-задачи, не удаляет при наличии других ссылок.
- **lastModifiedSingularity сохранение**: поле больше не теряется — сохраняется во всех upsert-операциях, гарантируя корректную работу Phase 2a.
- **forward/reverse изоляция**: `_failedIds` трекает упавшие forward-задачи, reverse sync пропускает их — ошибки forward не затираются.
- **Done date из journalDate**: `✅` теперь получает дату из `journalDate` (а не `start`).
- **Date-only без дублирования эмодзи**: date-only задачи не получают дублирующие `🛫`/`⏳`.
- **Строгое сравнение тегов**: `getTagName` использует точное совпадение, а не `includes()`, предотвращая ложное матчинг.
- **projectTag в syncHash**: добавлен в содержимое хеша для корректного отслеживания перемещений между проектами.
- **404-handling**: `softDeleteTask`/`archiveTask` возвращают `null` при 404 без Notice/console.error.

## 2.0.0 (2026-05-19)

### Added
- **Per-project task files**: задачи каждого проекта хранятся в отдельном файле `/project/{название}.md`. Задачи без проекта — в `/tasks/tasks.md`. Файл = принадлежность к проекту.
- **Section-aware I/O**: секция `#### 📝 Tasks` (настраиваемый маркер) — единственное место для задач в файлах проектов. Остальное содержимое файла (frontmatter, описание, другие секции) сохраняется.
- **Frontmatter `singularity-id`**: автоматическая привязка файлов Obsidian к проектам Singularity. Позволяет отслеживать переименования проектов.
- **Auto-create проектов**: forward sync создаёт проекты в Singularity, если Obsidian-задача ссылается на проект, которого нет в SG.
- **Rename detection**: при переименовании проекта в Singularity reverse sync переименовывает соответствующий файл в Obsidian.
- **Create/Update Project API**: `POST /project`, `PATCH /project/{id}`.
- **Теги проектов в Singularity**: при синхронизации forward sync создаёт тег с именем проекта в Singularity (для кросс-фильтрации).
- **`tasksSectionMarker` в настройках**: пользователь может настроить маркер секции задач (по умолчанию `#### 📝 Tasks`).

### Changed
- **Модель связывания проектов**: принадлежность к проекту определяется файлом, а не тегом. Тег `#my-project` в строке задачи больше не нужен — достаточно поместить задачу в `/project/My Project.md`.
- **`extractProjectTag()`**: без эвристики первого не-todo тега. Только контекст файла определяет `projectTag`. Для задач из `tasks.md` → `null`.
- **`processTask()`**: название проекта больше не добавляется в `obsidianTags`. `projectTag` заполняется, но не выводится как тег.
- **`writeTasks()`**: группировка задач по `projectTag`, роутинг в per-project файлы через `vaultWriter.writeTasksToFile()`.
- **`formatTaskLine()`**: фильтрует `projectTag` из `regularTags` — тег проекта не выводится в строку задачи.
- **`ensureProjectFiles()`**: читает frontmatter для `singularity-id`, переименовывает файлы при смене названия проекта, добавляет frontmatter в существующие файлы.
- **`resolveTags()`**: создаёт тег проекта в Singularity (ранее `projectTag` пропускался).

### Migration from v1.x
- Задачи в `tasks.md` с тегом `#my-project` теряют привязку к проекту. Перенесите их в `/project/My Project.md` вручную.
- После первого sync задачи с `externalId` автоматически мигрируют в соответствующие проектные файлы через reverse sync.
- Проектные файлы без `singularity-id` получат его автоматически при ближайшей синхронизации.

## 1.2.3 (2026-05-17)

### Fixed
- **Reverse sync blocked**: Reverse sync теперь обрабатывает задачи, уже существующие в Obsidian. Ранее `setSyncedObsidianIds` получал все ID, из-за чего reverse sync полностью пропускал задачи, которые forward sync не создавал.
- **Done-статус из Singularity**: Reverse sync включает архивированные задачи (`includeArchived=true`). Задачи, отмеченные выполненными в Singularity, теперь отмечаются `[x]` в Obsidian.
- **Возврат из архива**: Forward sync проверяет `checked` статус SG-задачи. Если в SG задачу вернули в невыполненные, forward sync не архивирует её повторно.
- **Undone в Obsidian**: Если SG говорит `checked=0` (не выполнено), reverse sync обновляет строку в Obsidian обратно в `[ ]` без `✅`.
- **Duplicate строк в файле**: `extractLineDescription` и `_emojiDatesRe` исправлены — больше не оставляют `:00.000` в extracted description, не плодят дубликаты.
- **API key leak**: TaskStore.saveFn скрабит `singularityApiKey` и сохраняет `syncState` + `habitState`.
- **Conflict resolver**: Парсинг `modificatedDate` через `parseSgDate()` — корректно обрабатывает ISO-строки, Unix-секунды и Unix-миллисекунды.
- **Ошибки инициализации**: Guard на `view.loadState`, null-safe `loadData()` в `resetAndSync`.
